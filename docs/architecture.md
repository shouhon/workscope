# 構成と処理の境界

## 現在の構成

Goの単一モジュール `workscope` から、Windows用の実行ファイルを1つ作成する。言語は利用者の指定によりGoとし、現在は標準ライブラリだけで構成する。Goの最低版は [go.mod](../go.mod) を参照する。

| 場所 | 現在の責務 |
| --- | --- |
| `cmd/workscope/main.go` | 引数と出力先を `cli.Run` に渡し、返されたコードで終了する |
| `internal/cli` | 引数、ヘルプ、版表示、日本語・JSON表示、終了コード。開始記録と照合を呼び出す |
| `internal/baseline` | Gitルートと管理領域、許容パス、対象の種類とハッシュ、インデックス、開始記録の保存・照合 |
| `internal/version` | CLI版番号の正本を提供する |
| `scripts` | 検査とローカルビルド。生成物は `dist/` に分ける |

アプリはネットワークへ接続せず、常駐処理を持たない。環境変数によるアプリ設定も設けていない。保存・JSON形式は[要件定義書](requirements.md)の `schema_version: 1` を使う。M1の開始記録をM2の `check` で読み取り、保存形式を変更せず照合する。

## 後続実装で守る責務と読み書き

開始記録をM1、照合と結果表示をM2で実装した。Windowsでの全体の受入確認はM3で行う。

| 処理 | 入力・読み取り先 | 許す書き込み・出力 |
| --- | --- | --- |
| 引数と許容範囲 | 引数、Gitルート、パスの実体 | 検証済みのルート相対パス。ルート外と管理領域を拒否する |
| Gitの状態取得 | Gitの機械処理向け出力、HEAD、インデックス | 取得結果だけを返す。Gitの設定・インデックスを更新しない |
| 対象の読み取り | 追跡中と無視されていない未追跡ファイル、リンク自体 | 種類、SHA-256、リンク先の文字列。ファイル本文は記録しない |
| 開始記録 | 対象とGitの状態、記録先の識別情報 | `begin` だけがルート直下の `.workscope/baseline.json` を保存する |
| 照合 | 開始記録、現在の対象とGit状態 | 差分と判定不能の理由。開始記録を更新しない |
| 結果表示 | 比較結果と照合範囲 | 日本語表示、またはJSONオブジェクト1件と終了コード |

Gitの呼び出しは `os/exec` の引数配列で行い、ファイル名をシェルの命令に組み込まない。Gitルートを明示し、パスを含む出力はNUL区切りで扱う。`git status` は通常インデックスを更新し得るため、読み取り用途では `--no-optional-locks` を付ける。[Git statusの仕様](https://git-scm.com/docs/git-status)と[Git diffの仕様](https://git-scm.com/docs/git-diff)を解析処理の根拠とする。

## M1の取得と保存

Gitの管理領域は `rev-parse` で特定し、`.git` がディレクトリとは仮定しない。親プロセスの `GIT_*` 環境変数を子Gitへ引き継がず、作業場所から特定したルートとインデックスを使う。任意の監視処理を起動しないよう `core.fsmonitor=false`、古い未追跡情報を使わないよう `core.untrackedCache=false` をコマンド単位で指定する。設定ファイルは変更しない。

追跡対象とインデックスは [`ls-files --stage -z`](https://git-scm.com/docs/git-ls-files) から取得する。未追跡対象はディレクトリを順に読み、`check-ignore --no-index -z --stdin` で無視された配下への進入を避ける。追跡済みの無視対象はインデックス側から別途取得する。`status` は未追跡走査・サブモジュール走査・名前変更推測を無効にする。名前変更は削除と追加として保存する。

読み取りには標準ライブラリの [`os.Root`](https://pkg.go.dev/os#Root) を使い、各成分も `Lstat` で確認する。Windowsの実在する許容パスは [`GetLongPathNameW`](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-getlongpathnamew) で実名へそろえ、ハードリンクの別名を取り違えない。リンク自体の参照先文字列をSHA-256へ変換し、リンク先は開かない。リンクや通常のディレクトリでない親の配下は判定不能とする。現在のGoで未対応の種類として表れるジャンクションも、走査せず判定不能にする。ファイルのハッシュは逐次計算する。

対象全体を2回取得し、ファイルの種類・SHA-256、HEAD、インデックス、開始前の変更が一致することを確認する。各取得の前後にもHEAD・インデックスを比較し、読み取り中のファイルの実体・大きさ・更新日時を確認する。状態が取得後に変わることや、途中で変わって元に戻る操作の検出は保証しない。

開始記録は `tool`、`schema_version`、記録ID、実体のルート、UTC日時、HEAD、`allow`、`coverage`、`preexisting_changes`、`files`、`index` を保存する。対象パスの区切りは `/` とし、各配列はパス順で安定させる。`allow` の種類は `file`・`directory`・`future`、対象の種類は `file`・`directory`・`symlink`・`missing` とする。`future` はまだ存在しない許容パスであり、ディレクトリと同じく配下を許容する。サブモジュールが存在するときは `coverage` と問題へ示し、記録成功としない。

既存の `.workscope` は、正常な自分の記録だけが入った通常のディレクトリであることを確認する。空の既存ディレクトリ、別のファイル、破損、別ルート、未知の形式、リンクを勝手に再利用しない。保存時は専用の排他的なロックファイルを作り、既存記録が読み取り時の内容と同じかを確認する。同じディレクトリへ一時ファイルを作成し、書き込み・同期・クローズ後に置換する。以前の記録を先に削除しない。クラッシュでロックや一時ファイルが残った場合は、安全のため停止するので、利用者が内容と他の実行がないことを確認する。

## M2の照合と出力

記録の識別情報に加え、日時、相対パス、許容対象の種類、対象の種類とハッシュ、インデックスの形式を検証する。読めない形式や項目の欠落を変更なしへ丸めない。照合前後に開始記録のバイト列が同じことも確認し、同時に取り直された場合は判定不能とする。

ファイルの種類とSHA-256を開始記録と比較し、インデックスはモード・オブジェクトID・競合の段階をパスごとに別に比較する。許容対象の種類は開始時のものを使い、ファイルがディレクトリに変わっても許容範囲を配下へ広げない。Windowsでは大小文字と区切りを扱い、パスの成分境界で配下か判定する。

対象の読み取り失敗とサブモジュールはパスごとに保持し、2回の取得で一致した、他の読み取り可能な対象を照合する。サブモジュール配下には進入しない。開始時の対象が無視された未追跡パスへ変わった場合は、内容を開かず `coverage_changed` として保持する。判定不能のパスを削除と誤判定せず、判定不能と範囲外の事実を独立して出力する。親がリンクへ変わったときは配下を判定不能とし、安全に取得できたリンク自体の変化は報告する。HEAD変更は問題として保持しつつ、安定して取得できたファイルとインデックスの差分を報告する。取得自体の不整合で差分の根拠を確定できない場合は、照合成功としない。

開始前の変更は開始記録の一覧をそのまま返し、開始後の差分とは別にする。差分のJSON項目は[利用手順](../README.md#開始後の変更を照合する)に記載する。JSONはオブジェクト1件で、空配列を `null` にしない。終了コードは判定不能2、範囲外1、範囲外なし0の優先順で決める。

## 信頼する境界

- Gitの管理領域とworktreeの作業領域を区別する。`.git` がディレクトリであることを前提にしない。
- ファイルシステムの状態、Git出力、既存の開始記録を検証する。読取失敗、未対応形式、別ルート、取得中の不整合は判定不能として伝える。
- `src` と `src2` のような文字列の先頭一致を範囲判定に使わない。Windowsでの大小文字、区切り、同一パスを確認する。
- リンク先の内容を開かない。サブモジュールは除外した事実を伝え、完全な照合成功としない。
- 開始記録の保存は以前の正常な記録を失わない方法で実装する。既存記録は `--replace` なしで上書きしない。
- 範囲外の変更と判定不能は独立して保持し、要件定義書の優先順位で終了コードを選ぶ。Gitの変更済みの印だけで内容の変化を判定しない。

## 検証と配布

CLIは、出力先と引数を受け取る `cli.Run` を通してテストする。Gitとファイルの結合テストは一時リポジトリだけを使う。Windows固有のテストでは、削除共有を許さないハンドルで置換失敗を、共有を許さないハンドルで読取失敗を再現する。実行ファイルそのものの起動は `scripts/verify.ps1` と別途の受入確認で行う。

ローカル配布物は `scripts/build.ps1` が作成する `dist/workscope.exe` とする。Goの `-trimpath` を使い、ビルド時のローカルパスを成果物へ含めない。版番号は `internal/version/version.go` を直接参照し、`--version` に表示する。更新規則と照合手順は [AGENTS.md](../AGENTS.md) を正本とする。公開、署名、更新配信は未設定である。
