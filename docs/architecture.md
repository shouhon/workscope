# 構成と処理の境界

## 現在の構成

Goの単一モジュール `workscope` から、Windows用の実行ファイルを1つ作成する。言語は利用者の指定によりGoとし、現在は標準ライブラリだけで構成する。Goの最低版は [go.mod](../go.mod) を参照する。

| 場所 | 現在の責務 |
| --- | --- |
| `cmd/workscope/main.go` | 引数と出力先を `cli.Run` に渡し、返されたコードで終了する |
| `internal/cli` | ヘルプ、版表示、未対応引数の拒否。ファイルとGitにはアクセスしない |
| `internal/version` | CLI版番号の正本を提供する |
| `scripts` | 検査とローカルビルド。生成物は `dist/` に分ける |

アプリはネットワークへ接続せず、常駐処理を持たない。環境変数によるアプリ設定も設けていない。製品の保存形式とJSON出力は、後続の実装で[要件定義書](requirements.md)に合わせる。

## 後続実装で守る責務と読み書き

以下は設計上の境界であり、現時点で実装済みの機能ではない。処理が必要になった時点で `internal/` にパッケージを追加し、空の層は先に作らない。

| 処理 | 入力・読み取り先 | 許す書き込み・出力 |
| --- | --- | --- |
| 引数と許容範囲 | 引数、Gitルート、パスの実体 | 検証済みのルート相対パス。ルート外と管理領域を拒否する |
| Gitの状態取得 | Gitの機械処理向け出力、HEAD、インデックス | 取得結果だけを返す。Gitの設定・インデックスを更新しない |
| 対象の読み取り | 追跡中と無視されていない未追跡ファイル、リンク自体 | 種類、SHA-256、リンク先の文字列。ファイル本文は記録しない |
| 開始記録 | 対象とGitの状態、記録先の識別情報 | `begin` だけがルート直下の `.workscope/baseline.json` を保存する |
| 照合 | 開始記録、現在の対象とGit状態 | 差分と判定不能の理由。開始記録を更新しない |
| 結果表示 | 比較結果と照合範囲 | 日本語表示、またはJSONオブジェクト1件と終了コード |

Gitの呼び出しは `os/exec` の引数配列で行い、ファイル名をシェルの命令に組み込まない。Gitルートを明示し、パスを含む出力はNUL区切りで扱う。`git status` は通常インデックスを更新し得るため、読み取り用途では `--no-optional-locks` を付ける。[Git statusの仕様](https://git-scm.com/docs/git-status)と[Git diffの仕様](https://git-scm.com/docs/git-diff)を解析処理の根拠とする。

## 信頼する境界

- Gitの管理領域とworktreeの作業領域を区別する。`.git` がディレクトリであることを前提にしない。
- ファイルシステムの状態、Git出力、既存の開始記録を検証する。読取失敗、未対応形式、別ルート、取得中の不整合は判定不能として伝える。
- `src` と `src2` のような文字列の先頭一致を範囲判定に使わない。Windowsでの大小文字、区切り、同一パスを確認する。
- リンク先の内容を開かない。サブモジュールは除外した事実を伝え、完全な照合成功としない。
- 開始記録の保存は以前の正常な記録を失わない方法で実装する。既存記録は `--replace` なしで上書きしない。
- 範囲外の変更と判定不能は独立して保持し、要件定義書の優先順位で終了コードを選ぶ。Gitの変更済みの印だけで内容の変化を判定しない。

## 検証と配布

現在のCLIは、出力先と引数を受け取る `cli.Run` を通してテストする。実行ファイルそのものの起動は `scripts/verify.ps1` で別途確認する。Gitとファイルの結合テストは、後続工程で一時リポジトリを使って追加する。

ローカル配布物は `scripts/build.ps1` が作成する `dist/workscope.exe` とする。Goの `-trimpath` を使い、ビルド時のローカルパスを成果物へ含めない。版番号は `internal/version/version.go` を直接参照し、`--version` に表示する。更新規則と照合手順は [AGENTS.md](../AGENTS.md) を正本とする。公開、署名、更新配信は未設定である。
