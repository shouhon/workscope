# 開発計画

## 目標と参照先

[要件定義書](requirements.md)の受入条件を満たすCLIを、Windows 11とPowerShellで利用できる状態にする。M0の基盤、M1の開始記録、M2の開始後の照合と出力契約に続き、M3でWindowsでの受入確認を行う。

要件そのものは要件定義書、パッケージの責務と境界は[構成と処理の境界](architecture.md)、版番号と必須検証は[作業指示](../AGENTS.md)を正本とする。

## M0：開発基盤のセットアップ

- 成果物：要件定義書の移動、Goモジュール、起動処理、ヘルプ、版表示、テスト、ビルド・検証スクリプト、開発文書。
- 完了条件：要件定義書の内容を保持し、外部ライブラリなしでWindows実行ファイルを作成できる。未実装機能を明示し、利用可能と誤認させない。
- 検証方法：移動前後のファイルのSHA-256一致、`./scripts/verify.ps1`、生成した実行ファイルの終了コードと表示の確認。
- 依存事項：導入済みのGoとPowerShell。受入確認用のGit操作は一時リポジトリに限定する。
- 状態：完了。

## M1：対象の列挙と開始記録

- 成果物：Gitルート・worktreeの特定、許容パスの正規化、対象とインデックスの取得、`begin`、安全な状態保存。
- 完了条件：要件3・4の記録側を満たし、既存記録や別用途の状態ディレクトリを勝手に上書きしない。本文を保存せず、リンク先を走査しない。
- 検証方法：一時リポジトリで通常の作業ツリーとworktree、未追跡・無視・追跡済みの無視対象、種類変更、リンク、保存失敗、記録中の変更を確認する。
- 依存事項：M0。記録とGit出力の具体的な型を、要件の形式契約に対応させて確定する。
- 状態：完了。

## M2：開始後の照合と出力契約

- 成果物：`check`、内容と種類の比較、インデックスの別比較、範囲判定、日本語表示、JSON出力、終了コード。
- 完了条件：開始前の変更と開始後の再編集を区別でき、判定不能を成功へ丸めない。要件5の固定項目と終了コードを満たす。
- 検証方法：要件6の受入条件1〜3・5・7・8を、一時リポジトリで確認する。範囲外の変更と判定不能が同時にある場合も確認する。
- 依存事項：M1。
- 状態：完了。

## M3：Windowsでの受入確認

- 成果物：利用者向けの実行例、Windows固有の確認結果、受入条件に対応する自動テスト。
- 完了条件：要件6の全8項目を満たす。通常の作業ディレクトリとworktreeの両方で、対象と開始記録を許可なく変更しないことを確認する。
- 検証方法：Windowsで日本語・空白・大小文字・パス区切り・似た名前のディレクトリを確認する。改行を含むGit出力は解析用データで確認し、Windowsで作成できない名前を実ファイルで確認したと扱わない。リンクを作成できない環境では、該当検証を未確認として残す。
- 依存事項：M2。リンクを作れる環境と、読み取り失敗を再現できる一時リポジトリ。
- 状態：完了。確認の対応と結果は[受入確認](acceptance.md)を参照する。

## リスクと実装時の判断

| 項目 | 影響 | 対応・判断条件 |
| --- | --- | --- |
| Windowsのパス同一性とリンク・ジャンクション | 誤った重複排除、ルート外や管理領域の混入 | M1で実体と境界を検証し、判断できない対象を正常扱いしない |
| 取得中の再編集やHEAD・インデックスの変化 | 一貫しない開始記録や照合結果 | M1で取得前後を確認する方法を決め、不整合時は判定不能とする |
| 大量の対象・大きなファイル | 過大なメモリ使用、処理時間の増加 | ハッシュを逐次計算する。上限が必要なら根拠と利用者への通知を決め、黙って省略しない |
| Windowsでの既存記録の安全な置換 | 保存失敗時に正常な記録が壊れる | M1で同一ディレクトリ内の一時保存と置換を検証し、失敗時の既存記録を確認する |
| 公開先と配布条件 | 公開版とScoop定義の版・URL・ハッシュが一致しない | GitHub Releases・MIT・Scoop/ZIPを採用。[配布手順](distribution.md)に従い手元の作成と外部公開を分ける |

## M3の確認結果（2026-10-22）

- 既存の受入テストへ、改行・タブ入りの複数パスをGit出力の解析から比較・範囲判定・JSONへの往復まで通す確認を追加した。Windowsで作れない名前は解析用データであり、実ファイルでの確認と区別した。
- `scripts/acceptance.ps1` を必須検証へ組み込み、ビルド済みCLIを専用の通常リポジトリとworktreeの両方で起動した。終了コード0・1・2・64、単一JSON、日本語表示、開始前と開始後の変更の区別、ディレクトリ境界、インデックス、判定不能と範囲外の併記を確認した。
- 対象ファイル、各worktreeのインデックスとHEAD、共通Git設定、worktree固有設定、開始記録をSHA-256で比較した。記録の作成・明示した取り直し以外の更新がなく、拒否した操作や判定不能時も状態を保持することを確認した。
- Windows 11 Homeで、実際のシンボリックリンク・ジャンクション、読取失敗、記録置換失敗の既存テストをスキップなしで確認した。最終差分への `./scripts/verify.ps1` が成功し、生成した実行ファイルの版表示も正本と一致した。
- 読み取り専用の補助担当が確認漏れを独立点検し、追加後のテスト・スクリプト・対応表も静的確認した。実行結果と最終変更の確認は主担当が行った。対象版、実行ファイルのSHA-256、検査の対応と制限は[受入確認](acceptance.md)に記載した。
- CLIの配布単位 `dist/workscope.exe` は `0.3.0` から据え置いた。テスト・開発用スクリプト・文書だけの追加で、製品コードと保存・JSON形式を変更していないためである。外部依存を追加していない。

## M2の確認結果（2026-10-22）

- 機能追加として、CLIの配布単位 `dist/workscope.exe` を `0.2.0` から `0.3.0` へ更新した。保存・JSON形式は `schema_version: 1` を維持し、旧版の実行ファイルが実際に作成した開始記録を、新版の実行ファイルで読み取れることを確認した。要件文書の文書版は変更していない。
- 検証対象は、M1完了コミット `2a6b718` に今回のM2差分を加えたソースである。最終ソースに対する `./scripts/verify.ps1` が成功し、整形、`go vet`、全テスト、Windowsビルド、ヘルプ・版表示を確認した。ビルド済みCLIの版表示は正本と一致した。
- 一時リポジトリの自動テストで、開始前の未コミット変更の維持、同じ変更済みファイルの再編集、追加・削除・種類変更、似た名前のディレクトリ、未作成パスの配下、既存のファイルを許容した範囲、内容を戻しても残るインデックスの変化、追跡解除・新規追加・競合段階を確認した。
- HEAD変更と範囲外変更の併存、開始記録の欠落・破損・別ルート・未知の版・項目やハッシュの不正、サブモジュールの除外、worktreeの配下からの照合を確認した。開始時の対象が無視された未追跡パスへ変わった場合は、本文を開かず `coverage_changed` として判定不能にする。
- Windowsのハンドル共有制限で読取不能を再現し、読めた別のパスの範囲外変更と併記できることを確認した。実際のシンボリックリンクで、外部の内容を走査しないこと、参照先文字列の変化、親ディレクトリをリンクへ置き換えた場合のリンク自体の追加と配下の判定不能を確認した。大小文字・区切り・日本語・空白を含む許容パスも確認した。
- 読み取り専用の補助担当が独立確認を行い、親リンクの配下の問題が、読めたリンク自体の差分まで抑止することを指摘した。主担当が修正し、専用の回帰テストと必須検証で確認した。修正後の確認は主担当によるものである。
- 主担当がビルド済みCLIで別途受入確認を行い、JSONオブジェクト1件、同一条件の並び順、終了コード0・1・2・64、日本語表示、範囲外と判定不能の併記を確認した。照合・ヘルプ・版表示の前後で対象ファイル、インデックス、Git設定、開始記録のハッシュが不変であることを確認した。
- 外部依存を追加していない。M3の全体受入確認は未完了であり、Windowsで作れない改行入りのファイル名を実ファイルで確認したとは扱わない。
