# 開発計画

## 目標と参照先

[要件定義書](requirements.md)の受入条件を満たすCLIを、Windows 11とPowerShellで利用できる状態にする。M0の基盤に続き、今回の開発ではM1の対象列挙と開始記録を実装する。照合機能はM2で実装する。

要件そのものは要件定義書、パッケージの責務と境界は[構成と処理の境界](architecture.md)、版番号と必須検証は[作業指示](../AGENTS.md)を正本とする。

## M0：開発基盤のセットアップ

- 成果物：要件定義書の移動、Goモジュール、起動処理、ヘルプ、版表示、テスト、ビルド・検証スクリプト、開発文書。
- 完了条件：要件定義書の内容を保持し、外部ライブラリなしでWindows実行ファイルを作成できる。未実装機能を明示し、利用可能と誤認させない。
- 検証方法：移動前後のファイルのSHA-256一致、`./scripts/verify.ps1`、生成した実行ファイルの終了コードと表示の確認。
- 依存事項：導入済みのGoとPowerShell。受入確認用のGit操作は一時リポジトリに限定する。
- 状態：完了。

## M1：対象の列挙と開始記録

- 成果物：Gitルート・worktreeの特定、許容パスの正規化、対象とインデックスの取得、`begin`、安全な状態保存。
- 完了条件：要件3・4の記録側を満たし、既存記録や別用途の状態ディレクトリを勝手に上書きしない。本文を保存せず、リンク先を走査しない。
- 検証方法：一時リポジトリで通常の作業ツリーとworktree、未追跡・無視・追跡済みの無視対象、種類変更、リンク、保存失敗、記録中の変更を確認する。
- 依存事項：M0。記録とGit出力の具体的な型を、要件の形式契約に対応させて確定する。
- 状態：完了。

## M2：開始後の照合と出力契約

- 成果物：`check`、内容と種類の比較、インデックスの別比較、範囲判定、日本語表示、JSON出力、終了コード。
- 完了条件：開始前の変更と開始後の再編集を区別でき、判定不能を成功へ丸めない。要件5の固定項目と終了コードを満たす。
- 検証方法：要件6の受入条件1〜3・5・7・8を、一時リポジトリで確認する。範囲外の変更と判定不能が同時にある場合も確認する。
- 依存事項：M1。
- 状態：未着手。

## M3：Windowsでの受入確認

- 成果物：利用者向けの実行例、Windows固有の確認結果、受入条件に対応する自動テスト。
- 完了条件：要件6の全8項目を満たす。通常の作業ディレクトリとworktreeの両方で、対象と開始記録を許可なく変更しないことを確認する。
- 検証方法：Windowsで日本語・空白・大小文字・パス区切り・似た名前のディレクトリを確認する。改行を含むGit出力は解析用データで確認し、Windowsで作成できない名前を実ファイルで確認したと扱わない。リンクを作成できない環境では、該当検証を未確認として残す。
- 依存事項：M2。リンクを作れる環境と、読み取り失敗を再現できる一時リポジトリ。
- 状態：未着手。

## リスクと実装時の判断

| 項目 | 影響 | 対応・判断条件 |
| --- | --- | --- |
| Windowsのパス同一性とリンク・ジャンクション | 誤った重複排除、ルート外や管理領域の混入 | M1で実体と境界を検証し、判断できない対象を正常扱いしない |
| 取得中の再編集やHEAD・インデックスの変化 | 一貫しない開始記録や照合結果 | M1で取得前後を確認する方法を決め、不整合時は判定不能とする |
| 大量の対象・大きなファイル | 過大なメモリ使用、処理時間の増加 | ハッシュを逐次計算する。上限が必要なら根拠と利用者への通知を決め、黙って省略しない |
| Windowsでの既存記録の安全な置換 | 保存失敗時に正常な記録が壊れる | M1で同一ディレクトリ内の一時保存と置換を検証し、失敗時の既存記録を確認する |
| 公開先と配布条件 | モジュール名・配布物の扱いが確定しない | 公開の明示依頼がある時点で決める。セットアップではローカルビルドに限定する |

## 現在地

- 完了した対象：M0とM1。照合を含む受入条件の全体は達成済みと扱わない。
- 次の工程：M2の照合と出力契約。開始前の変更と追加編集の比較、インデックスの別比較、範囲判定を実装する。

## M1の確認結果（2026-10-22）

- CLIの機能追加として、製品版を `0.1.0` から `0.2.0` へ更新した。保存・JSON形式は要件どおり `schema_version: 1` とし、要件文書の文書版は変更していない。
- `./scripts/verify.ps1` が成功し、整形、`go vet`、全テスト、Windowsビルド、ヘルプと版表示を確認した。生成した実行ファイルの版表示が正本と一致した。
- 一時リポジトリで、追跡済みの無視対象、未追跡・無視対象、開始前の再編集とステージ状態、削除・種類変更、コミット前のHEAD、worktreeの配下からの記録、日本語・空白・区切り・大小文字、未作成パス、既存記録と別用途の保存先の保護を確認した。改行とタブはGit出力の解析用データで確認し、Windowsの実ファイル名で確認したとは扱わない。
- Windowsで実際のシンボリックリンクを作成し、外部の参照先を含めないことを確認した。ジャンクションは走査せず判定不能となる。読取不能と記録置換失敗をハンドルの共有制限で再現し、失敗時に正常な既存記録が保持されることを確認した。取得中の再編集も記録不能となる。
- 主担当が実行ファイルで別途受入確認を行った。記録JSONが1件であること、終了コード0・2・64、許可のない上書きの拒否、明示した取り直し、対象ファイル・インデックス・Git設定と、ヘルプ・版表示・未実装の `check` 実行時の開始記録の不変を確認した。
- 読み取り専用の補助担当が独立確認を行い、Windowsのハードリンク別名と未作成パスの重複を指摘した。主担当が実名取得と重複除外を修正し、回帰テストと必須検証で確認した。修正後の実行確認は主担当によるものである。
- 外部ライブラリの追加、利用者の対象ファイルやGit設定の変更、公開・タグ・リリース・配備は行っていない。`check` による内容・種類・インデックスの比較と、照合時の終了コード1はM2に残る。

## セットアップの確認結果（2026-10-22）

- 確認環境：Windowsの `amd64`、Go 1.27.3、PowerShell 7.6.7、Git 2.56.0.windows.2。
- 元の要件定義書と `docs/requirements.md` のSHA-256が一致し、旧パスが残っていないことを確認した。
- `./scripts/verify.ps1` が成功した。整形、静的検査、テスト、ビルド、実行ファイルのヘルプ・版表示を確認した。
- 生成した実行ファイルの版表示が、`internal/version/version.go` の初回版と一致した。CLI版番号は今回初めて設定したため、更新前のCLI版はない。要件文書の文書版は変更していない。
- 実行ファイルを空の一時作業ディレクトリで起動し、引数なし、未知のオプション、未実装の `begin` と `check --json` が終了コード64となり、標準出力が空で日本語の案内を標準エラーへ出すことを確認した。作業ファイルは作成されなかった。
- `dist/`、`.cache/`、`.workscope/` がGit管理から除外され、外部Goモジュールがないことを確認した。
- 主担当が実装時の検証と実行ファイルでの受入確認を分けて実施した。補助担当による独立評価は行っていない。
- Gitは `main` で初期化した。追跡先は未設定であり、コミット・プッシュ・外部公開は行っていない。
