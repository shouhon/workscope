# workscope 要件定義書

- 文書版: 1.0
- 状態: 初版・未実装
- 目的: 作業開始時からの変化を照合し、指定した作業範囲を外れた変更を報告する。

## 1. 利用場面と完成条件

LLMに修正を任せる時点で、利用者の未コミット変更が残っている場合に使う。開始時に存在した変更と、その後に生じた変化を分けて報告できることを完成条件とする。

例として、開始時から config.toml に変更があり、今回の対象が AGENTS.md だけの場合、config.toml が開始後も同じ内容なら範囲外の変更として扱わない。同じ変更済みファイルが開始後に再編集された場合は、その変化を検出する。

検出できるのは記録前後の状態の違いである。誰が変更したかの特定や、記録の間に変更されて元に戻された操作の検出は保証しない。

## 2. 初版の対象

- Windows 11・PowerShellで利用できる、非対話型のCLIとする。
- Git管理下の通常の作業ディレクトリと、Gitの追加の作業ツリー（worktree）を対象にする。Gitが利用できない場所はエラーとする。
- 追跡中のファイルと、Gitで無視されていない未追跡ファイルを照合する。追跡中であれば無視設定に一致するファイルも対象に含める。
- Gitで無視された未追跡ファイル、.git の管理領域、workscope自身の状態保存先は照合対象に含めない。この範囲を結果に明記する。
- 自動復元、コミット、ステージ操作、変更者の推定、常駐監視、他の3つのCLIとの連携は初版に含めない。

## 3. コマンド

| コマンド | 要件 |
|---|---|
| workscope begin --allow <対象> [--allow <対象> ...] [--json] | 開始時の状態と許容する対象を記録する。--allow は1つ以上必要。 |
| workscope check [--json] | 開始記録と現在の状態を照合する。記録は更新しない。 |
| workscope begin --replace --allow <対象> ... | 既存の開始記録を、明示的に取り直す。 |
| workscope --help / --version | 日本語の使い方、対象範囲、版番号を表示する。 |

Gitのルートを作業の基準にし、--allow の対象もルートからの相対パスで指定する。既存のファイルまたはディレクトリに加え、これから作るパスも指定できる。初版ではワイルドカードを扱わない。ディレクトリを指定した場合は配下を含める。

ルート外へ出る指定やGitの管理領域の指定は拒否する。パスの区切り、大小文字、空白、日本語を適切に扱い、src を指定したときに src2 を含めない。ファイルシステム上の同一パスを重複して数えない。

## 4. 開始記録と照合

- 記録はGitルート直下の .workscope/baseline.json に保存する。既存記録があれば、--replace がない限り上書きしない。
- .workscope が既に別用途で使われている場合は停止する。ツールの識別情報と保存形式の版で、自分の状態ファイルか判定する。
- 保存内容は、記録ID、ルートの実体、日時、HEAD、許容する対象、照合範囲、開始時のGit状態、各対象の種類とSHA-256とする。ファイル本文は保存しない。
- Git状態にある変更済みという印だけで照合せず、変更済みファイルの追加編集も内容のハッシュで検出する。
- 追加・変更・削除・ファイルの種類の変更を検出する。名前変更は、初版では削除と追加として報告してよい。
- シンボリックリンクはリンク自体と参照先の文字列を記録し、参照先の内容をたどらない。サブモジュールは初版の判定対象外として明示し、存在する場合は完全な照合とは扱わない。
- HEADの変更、別の作業ディレクトリの記録、未対応の保存形式、読めない対象、記録中の不整合があれば判定不能とする。読めなかった対象を変更なしとして扱わない。
- コミット対象を準備する領域（インデックス）の変化も別項目として報告し、範囲外のパスでステージ状態が変わった場合は範囲外の変更に含める。
- 状態ファイルは一時ファイルから置き換えるなどして保存する。保存失敗時に以前の正常な記録を壊さない。

.gitignore やGit設定は自動変更しない。状態用ディレクトリをGitの対象から除外する方法をヘルプで案内する。

## 5. 出力と終了コード

通常表示は日本語の簡潔な結果とし、開始前からあった変更、開始後の変更、範囲外の変更、判定不能の対象を分ける。JSON表示では、少なくとも次の項目を固定する。

| 項目 | 内容 |
|---|---|
| schema_version / tool / command | 保存・出力形式の版、workscope、begin または check |
| status | recorded / within_scope / out_of_scope / unknown / invalid_arguments |
| baseline_id / root / coverage | 開始記録の識別子、基準となるルート、実際の照合範囲 |
| preexisting_changes | 開始時に存在した変更の一覧 |
| changes_since_begin | 開始後の変化。パス、種類、記録時・現在のハッシュ、許容範囲内かを含む。 |
| index_changes / out_of_scope_changes | インデックスの変化、範囲外の変化 |
| issues | 機械判定用の code、日本語の説明、関係するパス |

JSON内の対象パスはルートからの相対パスとし、区切りを / に統一する。リンク先などの文字列はJSONとして適切にエスケープする。

| 終了コード | 意味 |
|---|---|
| 0 | 記録成功、または照合が完了して範囲外の変更なし。範囲内の変更は存在してよい。 |
| 1 | 範囲外の変更あり。 |
| 2 | 記録・読取・照合の失敗、対象外の状態などで判定不能。 |
| 64 | 引数の誤り。 |

範囲外の変更と判定不能が併存するときは終了コード2とし、両方の事実を出力する。--json 指定時は標準出力をJSONオブジェクト1件に保ち、進捗や診断は標準エラーに出す。

## 6. 受入条件

1. 開始前からある未コミット変更を再編集しなければ、開始後の変更と区別できる。
2. 同じ変更済みファイルを開始後に再編集すると、Git状態の印が変わらなくても検出する。
3. 許容したディレクトリの追加・変更・削除は範囲内と判定し、似た名前の別ディレクトリは範囲外と判定する。
4. 空白・日本語・改行などを含むパスで、誤った分割や範囲判定をしない。
5. 読取失敗、HEAD変更、開始記録の破損、対象外のサブモジュールがあっても成功扱いにしない。
6. リンク先の外部ファイルを走査せず、リンク自体の変化を検出する。
7. 対象ファイル、インデックス、Git設定を変更せず、許可なく開始記録を更新しない。
8. 同一条件で配列の並び順が安定し、JSONと終了コードが上記の契約に従う。

実装時には一時的なGitリポジトリでこれらを確認し、利用者の作業中のリポジトリを検証用に書き換えない。

## 7. 版管理と実装時に決める事項

本書の初版は1.0とする。CLIは未実装のため、今回のCLI版番号の更新は対象外。実装開始時の初回CLI版は0.1.0、保存・JSON形式は schema_version: 1 とし、版番号の正本を1か所に定めて --version と配布物を一致させる。

実装言語、実行ファイルの配布方法、大規模な対象での処理上限は実装時に決める。初版のためだけに共通基盤や他のCLIへの依存を追加しない。上限を設けた場合も、対象を黙って省略して成功扱いにしない。

## 9. 追加要件：タスク名ごとの開始記録

初版の要件を維持したまま、複数の作業の開始時点を手動コピーなしで保持できるようにする。

- `begin` と `check` に任意の `--task <名前>`（`--task=名前` も可）を追加する。指定した名前の記録だけを選択し、省略時は従来の `.workscope/baseline.json` を使う。最後に作成した記録へ自動で切り替えない。
- タスク別記録は `.workscope/task-<名前のUTF-8のSHA-256（64桁、小文字）>.json` に保存する。本文を保存しない要件と、状態保存先全体の除外は維持する。名前は完全一致で比較し、大小文字も区別する。
- 日本語と途中の空白を含む名前を扱う。明示した空の名前、前後の空白、パス区切り、制御文字、不正なUTF-8、複数の `--task` は引数の誤り（64）とする。
- 同名の記録は `--replace` がない限り上書きしない。`--replace` は選んだ記録だけを取り直し、別タスクの記録と従来の記録を変更しない。存在しない記録の `check` は判定不能（2）とし、別の記録を代用しない。
- 保存形式とJSON出力は `schema_version: 1` を維持し、タスク名を指定した場合だけ `task` を追加する。旧形式の記録は移動・変換せず読み取る。記録内の名前と保存先が一致しない場合も、記録を保護して停止する。
- 正常な専用記録だけが入った保存先を再利用する。別用途のファイル・リンク・破損・未知の形式・別ルートの記録がある場合は、別タスクを追加する場合でも停止する。保存時のロックと保存直前の再確認で、後から作られた同名記録も勝手に置き換えない。
- 各タスクは開始時点と許容範囲を持ち、同じ作業ツリー全体を照合する。`check` はどの記録も更新しない。

受入確認では、従来の記録と複数タスクの併存、それぞれの開始時点と許容範囲、同名の上書き拒否、選択した記録だけの取り直し、未記録名の拒否、保存失敗時の既存記録の保持を確認する。通常の作業ディレクトリとworktreeの両方を対象にする。

## 10. 追加要件：Git診断、進捗、個別ヘルプ

- Gitの失敗時は終了コード2と既存のJSON固定項目を維持する。`begin` の保存失敗も2とし、1は `check` の範囲外検出だけに使う。実行ファイルを直接起動して確認し、`go run` など起動用コマンドの終了コードと区別する。
- `issues[].code` は `git_not_found`（Git未検出）、`git_start_failed`（実行ファイルを検出したが起動失敗）、`git_ownership_rejected`（起動後の所有権拒否）を区別する。アクセス権限拒否は `git_permission_denied`、Git作業ツリー外は `git_not_repository`、設定の読取失敗は `git_configuration_error`、その他の起動後の失敗は `git_failed` とする。複数の操作が失敗した場合は個々の診断を保持し、具体的な原因を優先する。
- 通常表示と `issues[].message` は失敗した操作・原因・次の対処を簡潔に示す。`begin`・`check` の `--verbose` 指定時だけ詳細を表示し、JSONでは省略可能な `issues[].details` に含める。保存・JSON形式の `schema_version: 1` は維持する。
- 詳細では実際に選択したGitの実行パスと `git -C` の作業場所を、絶対パスを `/` 区切りにしたUTF-8のSHA-256で識別する。パスに含まれ得る秘密や個人名、任意の環境変数名・設定値、Gitの生の標準エラーは表示しない。起動前にGitを特定できなかった場合も区別する。
- 親の `GIT_*` を除外する安全境界を維持する。設定注入、設定ファイルの指定、作業領域の指定が親に存在したかを詳細に値なしで表示する。通常の設定探索条件とコマンド単位の固定設定も示し、設定ファイルの読込結果や利用者環境での原因を未確認のまま断定しない。
- 所有権エラーでは、所有者と内容を確認して信頼できるGitルート1件を `--trust-repository <絶対パス>`（`--trust-repository=絶対パス` も可）で指定する方法を案内する。この実行の子Gitすべてに `-c safe.directory= -c safe.directory=<確認したルート>` を渡し、既存の広い信頼指定も今回の1件へ絞る。相対パス・空・複数指定・ワイルドカード・制御文字・存在しないパスは引数の誤りとし、Gitルートの実体との一致も確認する。配下から起動でき、worktreeはその作業ツリーのルートを指定する。指定した信頼設定は開始記録にも恒久設定にも保存せず、`begin`・`check` の各実行で明示する。設定ファイルの変更、権限昇格、自動再試行は行わない。
- `begin`・`check` が長くかかる場合は、約1秒ごとに処理段階、その取得回で確認済みのファイル数、取得回（全2回）、経過時間を標準エラーへ表示する。Git待ちは操作名を表示し、ファイル走査と区別する。1秒未満で完了する場合は進捗を省略し、表示を始めた場合だけ終了時にも表示する。ファイル名・本文は進捗に出さず、JSONは標準出力の1オブジェクトを維持する。
- `begin --help`・`begin -h`・`check --help`・`check -h` は、必須・任意の引数、使用例、終了コードを日本語で表示し、0で終了する。ヘルプはGitや開始記録を必要とせず、状態を作成・更新しない。
